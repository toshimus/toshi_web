macOS ビルド環境構築マニュアル

Windows / macOS クロスプラットフォーム対応環境 (Update: v1.0)

プロジェクト概要

このドキュメントは、macOS上でのwxWidgetsを用いたC++アプリケーションのコンパイルと、ダブルクリックで起動可能なスクリプトの作成手順、およびOS間の技術的な違いをまとめたものです。

💡 OSごとの環境の違い：Homebrew と MSYS2

macOS環境で使用する「Homebrew」は、もともとUnixベースで作られているMacの標準システム上に、直接ネイティブなパッケージ（ソフトウェアやライブラリ）を追加・管理するためのツールです。

一方、Windows環境でよく用いられる「MSYS2」は、Windowsという全く異なるOSの上に、UnixやLinuxに似た開発環境（MinGW-w64など）を擬似的に構築するためのシステムです。
つまり、MacとWindowsではOSの根幹となる仕様が異なるため、開発に必要なツールを準備するための「土台のアプローチ」にこのような根本的な違いが存在します。
💡 共通の架け橋となるライブラリ（wxWidgets と SDL2）

OSの仕様や開発環境（HomebrewとMSYS2）に上記のような大きな違いがあるにもかかわらず、「wxWidgets」や「SDL2」といったライブラリは、両環境で全く同じように共通して使用することが可能です。

これらは「クロスプラットフォーム・ライブラリ」と呼ばれ、各OSの複雑な仕様の違いを内部で自動的に吸収する役割を持っています。
  • wxWidgets： ウィンドウやボタン、メニューなど、OSごとの標準的なデスクトップUIを描画することに長けています。
  • SDL2 (Simple DirectMedia Layer)： 高速な2D/3Dグラフィック描画、音声再生、コントローラー入力など、ハードウェアへの直接的かつ低遅延なアクセスに特化しています。
私たち開発者はこれらのライブラリを利用することで、「一つの同じC++のソースコード」を書くだけで、MacではMac用のアプリとして、WindowsではWindows用のアプリとして、それぞれのOSに最適化された状態でコンパイルし実行することが可能になるのです。

1. 事前準備（Mac側）

Macのターミナルで、まだwxWidgetsを導入されていない場合は、以下のコマンドでインストールをお願いします。

brew install wxwidgets

また、SDL2および、ゲームやエミュレータ開発でよく使われる標準的な拡張ライブラリ（フォント描画用の sdl2_ttf、画像読み込み用の sdl2_image、音声再生用の sdl2_mixer）を導入する場合は、続けて以下のコマンドを実行してください。

brew install sdl2 sdl2_ttf sdl2_image sdl2_mixer

2. Mac用ビルドスクリプト（build.sh）

以下のコードをコピーして、プロジェクトフォルダ内に build.sh という名前で保存してください。

#!/bin/sh

echo "[K.I.T.T.] Building Pixel Art Editor (Incremental Build for macOS)..."

# 1. 差分ビルド用のフラグ初期化
UPDATE=0
HEADER_CHANGED=0

# ヘッダーファイルに変更があった場合は全再コンパイルのフラグを立てる
for hpp in *.hpp; do
    if [ ! -f pixelart_app ] || [ "$hpp" -nt pixelart_app ]; then
        HEADER_CHANGED=1
        break
    fi
done

# 2. 各ソースファイルの更新チェックと個別コンパイル
for src in app.cpp app_canvas_events_core.cpp app_canvas_events_down.cpp app_canvas_events_move.cpp app_canvas_events_up.cpp app_canvas_render.cpp app_image_ops.cpp app_ui_1.cpp app_ui_2.cpp canvas_io.cpp drawing_tools.cpp state.cpp vector_utils.cpp app_icons.cpp advanced_tools.cpp; do
    obj="$src.o"
    if [ ! -f "$obj" ] || [ "$src" -nt "$obj" ] || [ $HEADER_CHANGED -eq 1 ]; then
        echo "[Compile] $src ..."
        g++ -O2 -std=c++17 -c "$src" -o "$obj" `wx-config --cxxflags`
        if [ $? -ne 0 ]; then
            echo "[Error] C++ compilation failed at $src."
            exit 1
        fi
        UPDATE=1
    fi
done

# 3. 変更があった場合のみリンク処理
if [ $UPDATE -eq 1 ] || [ ! -f pixelart_app ]; then
    echo "[Link] pixelart_app ..."
    # 修正箇所: advanced_tools.cpp を advanced_tools.cpp.o に修正しました
    g++ -O2 app.cpp.o app_canvas_events_core.cpp.o app_canvas_events_down.cpp.o app_canvas_events_move.cpp.o app_canvas_events_up.cpp.o app_canvas_render.cpp.o app_image_ops.cpp.o app_ui_1.cpp.o app_ui_2.cpp.o canvas_io.cpp.o drawing_tools.cpp.o state.cpp.o vector_utils.cpp.o app_icons.cpp.o advanced_tools.cpp.o -o pixelart_app `wx-config --libs core,base`
    if [ $? -ne 0 ]; then
        echo "[Error] Linking failed."
        exit 1
    fi
    echo "[Success] Application is ready: ./pixelart_app"
else
    echo "[Skip] Everything is up-to-date. No compilation needed."
fi

その後、ターミナルで chmod +x build.sh を実行して実行権限を付与し、./build.sh で実行できるようにしましょう。

chmod +x build.sh

3. 起動用スクリプトファイル（.command）の作成

ターミナルで対象のプロジェクトフォルダ内に移動している状態で、以下のコマンドを実行してください。これにより、現在ターミナルが作業しているフォルダへ直接ファイルが作成されます。

cat << 'EOF' > KITT_Boot.command
#!/bin/sh
cd "$(dirname "$0")"
chmod +x build.sh
./build.sh
EOF

作成後、同じくターミナルで以下のコマンドを実行し、ファイルに実行権限を付与します。

chmod +x KITT_Boot.command
💡 chmod +x についての補足

このコマンドは、作成したファイルに対して「プログラムとして実行する権限」を与えるためのものです。
Macの初期設定では新規作成されたファイルは単なるテキストファイルとして扱われるため、このコマンドを実行することで安全なプログラムとして認識させます。

※この操作はファイル作成直後に「一度だけ」実行すれば問題ありません。
再起動を行ったり、ファイルの中身を書き換えたりしても権限は保持されます（ファイルを完全に削除して作り直した場合のみ、再度実行が必要です）。
💡 ワンポイントアドバイス

KITT_Boot.command 内の cd "$(dirname "$0")" という記述が、自動的に「そのファイル自身が置かれているフォルダ」を認識して移動する役割を果たします。そのため、プロジェクトフォルダ全体を別の場所へ移動させたとしても、中にある KITT_Boot.command をダブルクリックするだけで、常に正しいフォルダでコンパイルと起動が実行されます。

4. 使い方と実行後の流れ

設定完了後、フォルダ内にある KITT_Boot.command をダブルクリックしてください。

  • 初回ビルド時: 全てのソースファイルが順次コンパイルされ、最後にリンク処理が行われて実行ファイル pixelart_app が生成されます。
  • 2回目以降のビルド時: ソースコードやヘッダーファイルに変更がない場合は自動でビルドがスキップされ、変更があった部分のみが効率よくコンパイル（差分ビルド）されます。

5. WindowsバッチファイルとMacスクリプトの違い

Windowsの「バッチファイル（.bat）」と、Macの「シェルスクリプト（.sh / .command）」は、どちらも複数のコマンドを自動実行するためのファイルですが、記述言語や文法に違いがあります。

💡 主な違い
  • Windows (.bat): コマンドプロンプト（cmd.exe）で動作します。実行結果の判定には %ERRORLEVEL% を使用することが多いです。
  • Mac (.command / .sh): Unix系のシェル（bashやzsh）で動作します。ファイルの先頭に #!/bin/sh（シバン）を記述し、実行する環境を明記するのが特徴です。実行結果の判定には $? を使用します。

【例題】シンプルなビルドと実行の比較

Windowsの場合（build.bat）

@echo off
echo [K.I.T.T.] Building on Windows...
g++ -O2 main.cpp -o app.exe
if %ERRORLEVEL% equ 0 (
    echo [Success] Starting app...
    app.exe
) else (
    echo [Error] Build failed.
)
pause

Macの場合（build.command）

#!/bin/sh
cd "$(dirname "$0")"
echo "[K.I.T.T.] Building on macOS..."
g++ -O2 main.cpp -o app
if [ $? -eq 0 ]; then
    echo "[Success] Starting app..."
    ./app
else
    echo "[Error] Build failed."
fi

6. 動的ライブラリ（DLLとdylib）の利用パターンの違い

Windowsにおける動的リンクライブラリは「DLL（.dll）」と呼ばれますが、Macでは「dylib（.dylib）」と呼ばれます。これらをC++のコードでクロスプラットフォームに設計し、両方のOSでコンパイルできるようにするための標準的なパターンをご紹介いたします。

💡 エクスポート定義の分岐

ライブラリ内の関数を外部プログラムから呼び出せるように公開（エクスポート）する仕組みがOS間で異なります。
Windowsでは __declspec(dllexport) を指定する必要がありますが、Mac（GCC/Clang環境）では __attribute__((visibility("default"))) を使用します。C++のプリプロセッサを利用し、これをマクロで自動的に切り替えるのが一般的な手法です。

【例題】クロスプラットフォーム対応のライブラリ用ヘッダー（mylib.h）

#pragma once

// コンパイルするOSごとにエクスポート用のマクロを切り替える
#ifdef _WIN32
    // Windows環境用
    #define EXPORT __declspec(dllexport)
#else
    // Mac(Unix)環境用
    #define EXPORT __attribute__((visibility("default")))
#endif

// C言語形式で関数をエクスポートし、名前修飾(マングリング)を防ぐ
extern "C" EXPORT void kitt_initialize();
extern "C" EXPORT int kitt_calculate(int a, int b);

【例題】ライブラリの実装側（mylib.cpp）

#include <iostream>
#include "mylib.h"

// ヘッダーで定義した通り、C言語形式でエクスポートされる関数を実装します
extern "C" EXPORT void kitt_initialize() {
    std::cout << "[K.I.T.T.] System initialized. Ready to assist." << std::endl;
}

extern "C" EXPORT int kitt_calculate(int a, int b) {
    std::cout << "[K.I.T.T.] Calculating: " << a << " + " << b << std::endl;
    return a + b;
}

【例題】コンパイルコマンドの違い

ソースコード（mylib.cpp）をコンパイルして動的ライブラリを生成する際のコマンドも異なります。

Windowsの場合（.dll の生成）

g++ -shared -O2 mylib.cpp -o mylib.dll

Macの場合（.dylib の生成）

g++ -dynamiclib -O2 mylib.cpp -o libmylib.dylib
